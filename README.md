# SpatialChat — 바탕화면 위 공간형 실시간 채팅

피그마 멀티플레이어 느낌으로, 초대받은 사람(최대 5명)이 각자 **캐릭터**가 되어
**바탕화면 위에 떠 있고**, 캐릭터를 클릭해 입력하면 **오른쪽에 말풍선**으로 채팅이 뜹니다.
채팅방(목록형)이 아니라 하나의 공간을 공유하는 방식입니다.

- **데스크탑 껍데기**: Electron (투명 + 항상 위 + 클릭 통과 오버레이 창)
- **실시간 동기화**: Firebase Realtime Database (위치·말풍선·접속 상태)
- **정원**: 한 공간 최대 5명 (트랜잭션으로 보장)

---

## 1. Firebase 설정 (최초 1회)

1. [Firebase 콘솔](https://console.firebase.google.com)에서 프로젝트 생성
2. **빌드 → Realtime Database → 데이터베이스 만들기** (테스트 모드로 시작해도 됨)
3. **프로젝트 설정 → 내 앱 → 웹(</>) 추가** → 표시되는 `firebaseConfig` 복사
4. `src/firebase-config.js` 의 값을 본인 것으로 교체
   (특히 `databaseURL` 이 비어 있으면 안 됩니다)
5. (권장) 보안 규칙을 `database.rules.json` 내용으로 교체

---

## 2. 설치 & 실행

```bash
cd spatial-chat
npm install
npm start
```

실행되면 입장 화면에서 캐릭터 + 닉네임을 고르고, 둘 중 하나를 택합니다:

- **방 만들기** — 안 쓰는 6자리 코드를 발급해 새 공간을 엽니다. 입장 직후 코드가 안내되고,
  상단 "초대코드 복사"로 친구에게 전달합니다
- **참여하기** — 받은 코드를 입력합니다. **없는 코드면 입장이 막히고 안내가 뜹니다**
  (예전엔 오타를 내면 조용히 새 방이 만들어져서, 빈 방에 혼자 앉아 있게 됐습니다)

방은 마지막 사람이 나가면 사라지므로, 아무도 없는 코드는 "없는 공간"으로 처리됩니다.

조작:

| 동작 | 방법 |
|---|---|
| 캐릭터 이동 | 내 캐릭터(보라색) **드래그** |
| 채팅 입력 | **Enter** 또는 캐릭터 클릭 (누굴 클릭하든 내 입력창이 열림) |
| 다른 앱에서 채팅 | `⌘/Ctrl + Shift + Enter` (창을 띄우면서 입력창 열기) |
| 전송 / 취소 | 입력창에서 `Enter` / `Esc` |
| 대화 기록 | 상단 **대화보기** (안 읽은 수 뱃지 표시) |
| 오버레이 숨기기 | `⌘/Ctrl + Shift + Space` |
| 종료 | 상단 **나가기**, 또는 `Esc` **두 번**(2초 안에) |

말은 항상 내 캐릭터에서 나갑니다. 귓속말은 없습니다.

> 배경(다른 앱) 클릭은 그대로 통과됩니다. 캐릭터·입력창·상단 바 위에서만 클릭이 잡힙니다.

## 데이터 구조 (Realtime DB)

```
rooms/
  {ROOMCODE}/
    members/
      {memberId}/
        char   "🐱"
        name   "민지"
        x      0.42        // 화면 가로 비율 (0~1)
        y      0.55        // 화면 세로 비율 (0~1)
        msg    "안녕"       // 현재 말풍선 텍스트 ("" 면 없음)
        msgAt  1718000000  // 서버 타임스탬프(ms), 말풍선 만료 판정
    messages/
      {pushId}/
        uid    "-Nx..."    // 보낸 멤버 id (대화 기록에서 내 말 판별용)
        char   "🐱"
        name   "민지"
        text   "안녕"
        at     1718000000  // 서버 타임스탬프(ms)
```

- 접속 종료 시 `onDisconnect`로 멤버 노드 자동 제거 (접속자 목록 자동 정리)
- 좌표를 비율로 저장 → 화면 해상도가 다른 사람끼리도 상대 위치 유지
- `members`는 현재 상태(말풍선 1건), `messages`는 누적 기록 — 역할이 다릅니다

### 기록 수명

| 시점 | 동작 |
|---|---|
| 첫 사람 입장 | 이전 세션 잔재 전부 삭제 (강제 종료·크래시 대비) |
| 이후 입장 | 24시간 초과분 · 200개 초과분만 삭제 |
| 마지막 사람 퇴장 | 방 전체 소멸 |
| 대화 중 | 최근 100개만 구독해 표시 |

`rooms/$room` 노드엔 쓰기 권한이 없어 방을 직접 못 지웁니다. 대신 `messages`를 지우면
`members`가 이미 비어 있어 자식 없는 노드가 되고, RTDB가 알아서 방을 없앱니다.

## 다음 개선 아이디어

- **다중 모니터 지원** — 지금은 `getPrimaryDisplay()`만 써서 외장 모니터엔 안 뜬다
- **트레이 아이콘 상주 + 자동 시작** — 나가면 완전 종료라 재실행이 번거롭다
- **닉네임·캐릭터 기억** (`localStorage`) — 켤 때마다 다시 고른다
- 입퇴장 시스템 메시지 ("○○님이 들어왔어요")
- 말풍선 유지 시간을 글자 수에 비례하게
- 캐릭터가 화면 가장자리일 때 말풍선 위/아래로도 자동 회피
- 캐릭터 걸어다니는 애니메이션 / 이모지 리액션
- **Firebase 익명 인증** — 현재 규칙은 `.read/.write: true`라 초대 코드만 알면 누구나 접근 가능
